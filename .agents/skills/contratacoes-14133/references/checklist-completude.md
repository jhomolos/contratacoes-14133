# Checklist de Completude Processual

Use este roteiro no modo "checklist processual completo" da avaliação de completude (ver SKILL.md). O objetivo é verificar se, para a modalidade em questão, todos os documentos obrigatórios existem no processo e estão minimamente estruturados — não é uma revisão de mérito técnico linha a linha (isso é feito nos outros dois modos de avaliação).

## Passo 1: Identificar a modalidade

Pergunte a modalidade da contratação se não estiver clara — isso determina quais documentos abaixo são obrigatórios (ex.: dispensa de licitação normalmente dispensa alguns formalismos exigidos em pregão).

## Passo 2: Checklist de presença de documentos

Para cada item, marque presente / ausente / incompleto:

- [ ] Documento de Formalização de Demanda (DFD)
- [ ] Estudo Técnico Preliminar (ETP), cobrindo os 13 tópicos de `references/etp-topicos.md`
- [ ] Mapa de Riscos (anexo ou vinculado ao ETP)
- [ ] Termo de Referência (TR), conforme modelo AGU vigente para a modalidade
- [ ] Parecer Técnico, quando a modalidade exigir (ver `references/parecer-tecnico-topicos.md`)
- [ ] Outros documentos exigidos pela modalidade específica que o usuário tenha mencionado (ex.: justificativa de dispensa, pesquisa de preços formal, autorização da autoridade competente)

## Passo 3: Checklist de coerência entre documentos

Além de "existe ou não existe", verifique se os documentos são coerentes entre si — isso captura problemas que uma checagem de presença sozinha não pega:

- [ ] A necessidade descrita no ETP corresponde à necessidade do DFD (não foi substituída por outra solução no meio do caminho)
- [ ] Os riscos do Mapa de Riscos aparecem refletidos no modelo de gestão do contrato do TR
- [ ] As quantidades e a estimativa de valor são as mesmas entre ETP e TR (ou há justificativa clara para a diferença)
- [ ] O Parecer Técnico (quando existir) trata da modalidade correta e não de outra

## Passo 4: Reportar os achados

Apresente o resultado como uma lista organizada por documento (não como texto corrido), indicando claramente:
- O que está ausente
- O que está presente mas incompleto (e o que falta especificamente)
- O que está conforme

Isso permite ao usuário corrigir rapidamente os pontos pendentes antes de prosseguir no processo.
